Composer

The reply box under a conversation: a rounded field that grows with the text, Enter to send, Shift+Enter for a new line, and one round send button that stays disabled until there is something to send.

Usage

Use it when

  • The person writes the next message in a chat layout: to a tutor, an assistant, a support thread.
  • A single prompt box at the top of an empty assistant page, before any conversation exists.

Use something else when

  • A form field for a long answer that is saved, not sent (an essay, a description): use Textarea. Enter must add a line there, not submit.
  • Searching or filtering a list: use Search field.
  • A one-line value such as a name or an email: use Text field.
  • Jumping to a command or a page: use Command palette.

Where it goes. Directly under the message scroller, the width of the conversation column, outside the scroller so it never scrolls away. On phones it is the last thing on screen, padded by the safe area (safe-bottom), and rides above the keyboard. Extra tools (attach, voice) go to the left of the textarea; send is always last, on the right.

Examples

Anatomy

PartWhat it is
form.composerRequired. A <form> with data-lds-composer. Pill shaped (24 px radius); the ring appears when the textarea has focus.
textareaRequired. rows="1", labelled. Grows from one line to 200 px, then scrolls (field-sizing: content, with a JS fallback).
.composer__sendRequired. A 40 px round accent type="submit" button with aria-label="Send" and the arrow_upward icon. Disabled while the text is empty.
.icon-btnOptional tools before the textarea: attach a file, add an image.

States

StateHow
emptySend is disabled (35 % opacity, no finish). Enter does nothing.
focusAccent ring: 1.5 px inset plus a 4 px soft ring, over --d-fast.
typingSend enables as soon as the text has a non-space character.
sentThe form emits lds:send with { text }, clears the textarea, shrinks back to one line and keeps focus for the next message.
composing (IME)Enter while composing characters (Japanese, Chinese input) confirms the characters and does not send.

Motion and microinteractions

  • Send sinks to 0.9 on press and springs back on --spring-snappy (360 ms); enabling and disabling cross-fades opacity over --d-fast.
  • The focus ring transitions over --d-fast on --ease-standard.
  • Growth is not animated: each new line appears at once, so the caret never chases a moving box.
  • Reduced motion: the press and the ring become 120 ms linear changes.

Accessibility

  • Label the textarea (aria-label="Message" or a visible label). The placeholder is a hint, not the label.
  • Send is a real type="submit" button with aria-label="Send"; disabled while empty, so assistive tech reports why nothing happens.
  • Say the keys once near the box on first use ("Enter to send, Shift+Enter for a new line") with a hint, not in the placeholder.
  • After sending, focus stays in the textarea.

Do and don't

check_circleDo

  • Keep it outside the scroller, under the conversation.
  • Listen for lds:send; do not add your own Enter handling.
  • Put tools to the left and keep send last.

cancelDon't

  • Use it for a form answer that is saved, not sent: use a textarea.
  • Hide the send button and rely on Enter only.
  • Animate the box height or clear the text before the message is safely queued.

Behavior and code

Plain HTML. init() wires form[data-lds-composer]: Enter sends (not while composing), Shift+Enter adds a line, send is disabled while empty, the box grows to 200 px (native field-sizing, or a height fallback). On send it emits lds:send with { text } (bubbles), then clears and refocuses the textarea.
