Feature row

One feature told beside its proof: a short title, a paragraph and a few points on one side, a live stage with the feature working on the other. Rows alternate sides with feature--reverse.

descriptionView as Markdown

Usage

Use it when

  • Explaining one feature of a product on a landing page, next to the feature running.
  • Two to four features in a row of sections, where each needs its own demo.

Use something else when

  • Many small features of equal weight: use Layout primitives. Use an auto-grid of short text blocks; not every feature needs a stage.
  • Destinations people can open: use Link card.
  • The first screen of the page: use Hero.

Where it goes. Inside a marketing section. From 900 px the copy takes 5 of 12 columns and the stage 7 (reversed with feature--reverse); below that the copy comes first and the stage follows. Consecutive rows are 56 to 112 px apart.

Examples

Anatomy

PartWhat it is
.featureRequired. The two-column grid.
.feature--reverseStage first on wide screens.
.feature__copyRequired. Eyebrow, title, body and points.
h2/h3.feature__titleRequired. 24 to 32 px.
p.feature__bodyThe paragraph, max 52 characters a line.
ul.feature__pointsTwo or three facts, each li holding an icon and the text in a span.
.feature__stageRequired. The proof: live components on the quiet fill. Surfaces placed directly inside it (lists, key-value, code blocks, tool calls) switch to the base color, never fill on fill. Also usable on its own as a demo stage, for example in a hero.
.feature__stage--flushNo padding, for a stage that holds one full-bleed component.
.feature__captionA footnote that says what can be tried or that the content is an example.

Variants and sizes

Class or attributeWhen
feature--reverseStage on the left from 900 px.
feature__stage--flushStage without padding.

Motion and microinteractions

  • The copy may fade up once with reveal on scroll. The stage only moves when someone uses what is in it.
  • A view inside the stage that swaps (a code sample per platform) uses view swap: the new content rises 4 px from a 4 px blur over 240 ms on --ease-enter.

Accessibility

  • The copy comes first in the DOM in both directions; feature--reverse only changes the visual order on wide screens.
  • Every control in the stage keeps its label. Say in feature__caption when content is an example.

Do and don't

check_circleDo

  • Put one working feature in each stage.
  • Wrap point text in a span so inline code wraps with it.

cancelDon't

  • Use a screenshot when the component can run.
  • Make every feature a row; a list carries the smaller ones.
