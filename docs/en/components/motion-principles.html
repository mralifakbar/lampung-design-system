Motion principles

Calm by default: things arrive on a spring with no overshoot, leave faster on an accelerating curve, start from wherever they are when interrupted, and only bounce after a gesture that carried momentum. Every value comes from a token; the recipes in this group say which one.

Usage

Use it when

  • Before adding any motion: read this page, then pick the recipe that matches the situation instead of writing a new animation.
  • Choosing a duration or curve for a component the system does not have yet (then add it to the system, not the page).
  • Reviewing a screen that "feels slow", "feels cheap" or "jumps": check it against the six rules below.

Use something else when

  • A press on a control: use Press feedback.
  • Something opening, closing, arriving or leaving: use Enter and exit.
  • A marker moving between options (tabs, segmented, sidebar): use Sliding indicator.
  • Content opening or closing in the flow (accordion, dismiss): use Height expand.
  • A group of items arriving together: use List stagger.
  • Replacing one view with another in the same place: use View swap.
  • A thumbnail growing into a full view: use Shared element.
  • A number changing: use Number count.
  • Dragging, flicking, swiping: use Drag and momentum.
  • Figures appearing as the page scrolls: use Reveal on scroll.
  • What changes when people ask for less motion: use Reduced motion.

Where it goes. Everywhere, through tokens in css/tokens.css. Motion lives in the component CSS; pages do not add their own transitions to system components.

Examples

Variants and sizes

Class or attributeWhen
--d-instant (120ms)Hover tints, small color changes. Press uses 90 ms in the components.
--d-fast (160ms)Opacity and color, overlay fade-ins.
--d-exit (180ms)Anything leaving: menus, dialogs, toasts. Pair with --ease-exit.
--d-standard (240ms)Text swaps, tab panels, scrims, fades.
--d-snappy (360ms) + --spring-snappyDamping 1.0, response 0.27 s. Presses releasing, toggles, thumbs, small indicators, icon swaps.
--d-considered (480ms) + --ease-inoutThings already on screen changing value: progress bars, rings, chart data.
--d-smooth (560ms) + --spring-smoothDamping 1.0, response 0.42 s. Panels, sheets, dialogs, sliding indicators, height changes.
--d-momentum (600ms) + --spring-momentumDamping 0.8: a 1.5 % overshoot. Only after a released drag or flick.
--ease-entercubic-bezier(0.16, 1, 0.3, 1). Fades in, text, small reveals.
--ease-standardcubic-bezier(0.22, 1, 0.36, 1). Color and state changes.
--ease-inoutcubic-bezier(0.65, 0, 0.35, 1). Something already visible moving to a new value.
--ease-exitcubic-bezier(0.7, 0, 0.84, 0). Dismissals; accelerates away.

Motion and microinteractions

  • Respond on press. Feedback starts on pointer down, within 90 ms, and releases on --spring-snappy. See press feedback.
  • Enter slow, leave fast. Entrances 240 to 560 ms on a spring or --ease-enter; exits 160 to 260 ms on --ease-exit (180 ms for anything small, up to 260 ms for a sheet that travels its full height). Exits never bounce.
  • Same path back. What rose from the bottom drops to the bottom; drawers leave to their side; menus grow from and return to the corner nearest the trigger (transform-origin, menu--right, menu--up).
  • Bounce is earned. --spring-momentum only after a gesture that carried momentum (a flicked sheet, a released slide knob). Everything a tap opens uses damping 1.0.
  • Interruptible. Anything a person can reverse uses CSS transitions, which start from the current value. Keyframes only for one-shot events (a shake, a ring, an entrance that never reverses). Never block input while something moves.
  • Reduced motion. Under prefers-reduced-motion: reduce every transition becomes 120 ms linear, keyframes play once in 1 ms, dialogs and menus stop scaling, shimmer and sparks stop; spinners keep turning. See reduced motion.
  • Only transform, opacity, filter and grid-template-rows (for height) animate. Never top, left, width or height of things in the flow, except the few components that measure (text morph, confirm in place, toolbar labels).

Accessibility

  • Motion is never the only signal: every state change also changes words, an icon or a role/ARIA attribute.
  • Never block input during a transition; a second click redirects, it is not ignored.
  • No endless decorative loops. Loops that report work (spinner, shimmer, thinking) stop when the work stops.

Do and don't

check_circleDo

  • Pick a recipe from this group and its tokens before writing any transition.
  • Use transitions for state, keyframes only for one-shot events.
  • Leave on --ease-exit in 180 ms; enter on a spring.

cancelDon't

  • Invent durations or bezier curves on a page.
  • Bounce anything a tap opened, or fade-up every element on scroll.
  • Animate layout properties or use transition: all.
  • Make people wait for an animation before they can act.

Behavior and code

Plain HTML. Tokens are CSS custom properties; read them in JS with getComputedStyle(document.documentElement).getPropertyValue('--d-smooth'). Behaviors in js/lds.js already use them and already check prefers-reduced-motion.
