Data table

A table people work in: search, filter chips and menus, sortable headers, a column menu, row density, row selection with a selection bar, and pagination with a page size, all on a plain .table and wired by one hook. Every control changes the rows at once and says what it did.

descriptionView as Markdown

Usage

Use it when

  • A list of records people search, narrow, sort and act on in bulk: staff of a service portal, applicants, permit applications, bills.
  • More than about 20 rows, so paging and a page size help, and enough columns that some people want fewer.

Use something else when

  • A short, fixed table people only read: use Table. Plain .table, maybe with data-lds-sort.
  • One or two facts per item, mostly on phones: use List.
  • Thousands of rows from a server: use Table. Render the page the server returns into a .table and keep the same bar and footer markup; this hook works on the rows in the page.
  • Files people recognize by type or picture: use File tile.

Where it goes. Full width of the content column. The bar sits above the table (search first, filters next, tools at the end), the footer below it (the count on the left, page size and pager on the right). The selection bar floats at the bottom of the window while rows are ticked. On phones the search takes its own row, the tools wrap, the table scrolls sideways in its box and the pager keeps only previous, current and next.

Anatomy

PartWhat it is
.dtable[data-lds-table]Required. The wrapper and its container query. The attribute value names the table so density, page size and hidden columns are remembered; data-page-size (default 10) and data-noun ("members") set the defaults and the words of the count.
.dtable__barThe toolbar: .control.search.dtable__search with input[data-lds-table-search], filters, then .dtable__tools.
[data-lds-table-filter="key"]A filter on data-key of each row. On a .chip-row[data-lds-chips] the chip values are the choices; on menuitemcheckbox items (with data-lds-keep-open) data-value is. Several values of one key match any; different keys must all match.
.dtable__filter-countOptional [data-lds-table-filter-count="key"] badge on a filter button: how many values are on.
[data-lds-table-col="key"]menuitemcheckbox items that show or hide the column whose th has data-col="key". The last visible column cannot be hidden.
[data-lds-table-density].toggle buttons with regular and compact (40 px rows) in a .toggle-group.
th[data-col] > buttonA sortable header: ascending, then descending, then unsorted. aria-sort on a th sets the first sort. A cell's data-sort overrides its text (dates, names with titles).
.dtable__selectThe checkbox column: input[data-lds-select-all] in the header (visible rows), input[data-lds-select] per row, each with an aria-label. Needs data-lds-selection="selbarId" on the wrapper.
tr.dtable__emptyRequired. One row spanning all columns with an empty state and a [data-lds-table-reset] button; shown when nothing matches.
tr.dtable__state[data-state]Optional loading (skeleton cells) and error (alert with retry) rows, shown by tableState().
.dtable__foot[data-lds-table-info] count, [data-lds-table-size] menu items with a [data-lds-table-size-label], and .pager[data-lds-table-pager] that the hook fills.

Motion and microinteractions

  • Results arriving after a search, filter or page change blur in 25 ms apart (capped at the tenth row) on --ease-enter over --d-standard, the list stagger recipe. Sorting reorders at once, as the table spec asks.
  • The sort arrow turns on --spring-smooth; filter counts pop in on --spring-snappy; menu checks scale in on --spring-snappy.
  • The selection bar rises on --spring-smooth and its count rolls; the header checkbox draws its tick or dash.
  • A refused action (hiding the last column) shakes the item.
  • Reduced motion: rows fade in 120 ms with no blur or travel.

Accessibility

  • It is a real <table>: headers are th, sort buttons are real buttons and only the sorted th has a non-none aria-sort.
  • The search has an aria-label; chips are toggle buttons with aria-pressed; menu filters and columns are menuitemcheckbox with aria-checked, page sizes menuitemradio.
  • Sorting, paging and clearing a selection are announced through the shared live region; the count is aria-live="polite".
  • After a page change focus stays on the pager (on the current page if the button you pressed went away) and the table scrolls into view.
  • Every row checkbox names its row ("Select Rina Wijaya"); the header one says "Select all members on this page". Escape inside the table clears the selection.
  • The .table-box gets tabindex="0" and an aria-label so keyboard users can scroll it sideways.

Do and don't

check_circleDo

  • Put the most used filter on chips and the rest in menus.
  • Give rows data-* values in lowercase for filters, and data-sort for dates.
  • Say what the count counts with data-noun.

cancelDon't

  • Add a Filter button that opens a dialog for two or three filters; chips and menus are faster.
  • Animate re-sorting or let the table change height on every keystroke; the footer keeps its place.
  • Hide the name column behind the column menu.

Behavior and code

Plain HTML. data-lds-table wires everything named above and fires lds:table with { total, page, pages, shown } after each change. data-lds-selection="selbarId" on the same element wires the checkboxes and the bar (lds:select with { count, items }). After adding or removing rows call tableRefresh(el); to show loading or error rows call tableState(el, "loading" | "error" | "ready").
