# Examples

Three examples built only from Lampung Design System (`css/lds.css` + `js/lds.js`), all for a fictional local government, **Pemerintah Kota Contoh**. The example apps are in Indonesian; this file is for contributors.

| Page | File | Built by |
|---|---|---|
| Hub (Indonesian) | `docs/examples/index.html` | Generated by `npm run build:examples`. Do not edit by hand. |
| Hub (English) | `docs/examples/en/index.html` | Generated by `npm run build:examples`. Do not edit by hand. |
| Sakai Dasbor, the city operations dashboard | `docs/examples/dashboard/<slug>.html` | Generated from `docs/examples/src/dashboard/<slug>.html` |
| Aplikasi warga Sakai, the citizen app | `docs/examples/mobile.html` (+ `mobile.css`, `mobile.js`) | Hand written |
| Portal layanan publik, the public portal | `docs/examples/landing.html` (+ `landing.css`) | Hand written |

"Sakai" comes from the Lampung phrase *sakai sambayan*, working together and helping each other.

The rest of this file is how to add or change a Sakai Dasbor page. Read it fully before you start. These pages show every rule below in practice; open their sources side by side with this file:

- `src/dashboard/ringkasan.html`: KPI strip, chart cards, a donut, a small data table, an activity feed, period switch, Pratinjau keadaan on every widget.
- `src/dashboard/pengguna.html` and `laporan.html`: a full data table (search, chips, menu filters, sort, columns, density, selection bar, page size, pager, row menu, invite form, loading, empty and error rows).
- `src/dashboard/tindak-lanjut.html`: a kanban board with search, filters, a detail drawer and a new-card drawer.
- `src/dashboard/kalender.html`: an event calendar with a calendar filter list, an upcoming list, an event popover and a new-event modal.
- `src/dashboard/masuk.html`: a page without the app frame (sign in), with the shared `dash-auth` layout and `auth.js`.

## 1. How a page is built

```
docs/examples/src/dashboard/<slug>.html   you write this (a fragment with front matter)
scripts/build-examples.mjs                wraps it in the shared frame, validates it, writes both hubs
docs/examples/dashboard/<slug>.html       generated; never edit it
docs/examples/dashboard/dashboard.css     placement only, one section per page
docs/examples/dashboard/dashboard.js      shared behavior and helpers (notify, delay, showState)
docs/examples/dashboard/auth.js           helpers for the pages without the frame (field errors, password strength)
```

The frame gives every page, without any work from you: the app shell sidebar (groups Dasbor, Halaman, Masuk, current page highlighted, foldable rail on wide screens, drawer under 960 px), the app bar (breadcrumbs, Cari halaman, Tampilan menu, Notifikasi, account menu), the command palette (⌘K, Ctrl+K or `/`; lists every page), the page header (title, the example note, description, your actions, and a Pratinjau keadaan menu when the page has `data-states` widgets), the page layer host, the skip link, theme restore before paint and `init()`. Every frame label is Indonesian and the document is `lang="id"`.

**The example note.** Every page shows "Contoh. Data fiktif, bukan layanan resmi." exactly once, and the build fails otherwise. Shell pages get it in the page header (or at the end of `main` when `header: false`). Pages with `shell: false` place the token `{{note}}` where it belongs, usually in `.dash-auth__foot`. Do not add a second one.

The slug, title, group, sidebar icon and English name (for the English hub) of every page live in the `PAGES` list at the top of `scripts/build-examples.mjs`. Add a line there when you add a page (keep the order); slugs are Indonesian kebab-case.

## 2. The source file

```html
---
title: Pendapatan daerah
description: Pajak dan retribusi daerah November 2026 terhadap target.
---
<template data-slot="actions">
  <button class="btn btn--secondary btn--md" type="button">…</button>
  <button class="btn btn--primary btn--md" type="button">…</button>
</template>

<template data-slot="layers">
  <!-- optional: scrims, drawers, dialogs that belong in the fixed layer host -->
</template>

<!-- the page body: your sections, in order -->

<script type="module">
import { tableRefresh } from '../../../js/lds.js';
import { notify, delay, showState } from './dashboard.js';
// page behavior only
</script>
```

Front matter (one `key: value` per line):

| Key | Required | Meaning |
|---|---|---|
| `title` | yes | The `<h1>` and the window title. Sentence case, Indonesian. |
| `description` | yes | One sentence under the title and the meta description; also shown on the Indonesian hub. Specific, no buzzwords. |
| `group` | no | Only for pages not in `PAGES`. |
| `crumb` | no | Overrides the last breadcrumb (default: the title). |
| `shell` | no | `false` for pages without the app frame: masuk, daftar, lupa-kata-sandi, verifikasi, akses-ditolak, segera-hadir. The body then sits in `<main class="dash-solo">` and you build the whole screen with the `dash-auth` classes. Include `{{note}}`, a way back (a link to `ringkasan.html`) and an appearance switch (`seg` with `data-lds-theme`). |
| `header` | no | `false` to drop the generated page header (only when the page has its own, such as the profile cover). |
| `wide` | no | `true` removes the 1600 px max width (boards, inbox, chat, archive, command center). |

Slots: `<template data-slot="actions">` goes into the page header next to the Pratinjau keadaan menu (at most one primary button, one or two secondary ones). `<template data-slot="layers">` goes into the fixed `.layer-host`, which is where `.scrim` + `.drawer`, `.scrim` + `.dialog` and toasts belong so they cover the window. Native `dialog.modal` can stay in the body. Every `<script type="module">` is moved after the shared script, so `init()` has already run.

### Content and data

- The city is fictional: Pemerintah Kota Contoh, about 1,1 juta residents in nine kecamatan with generic names (Kecamatan Utara, Selatan, Timur, Barat, Tengah, Pesisir, Bukit, Teluk) and kelurahan such as Sukamaju or Mekarsari. Offices follow the pattern "Dinas … Kota Contoh". Never name a real agency, a real national program, a real company or a real person, and never make a claim about one.
- Everything a person reads is Indonesian: plain, polite, sentence case, buttons named for their outcome ("Teruskan ke dinas", "Simpan perubahan"), no em dashes. aria-labels too. Code and comments stay English.
- Today is Monday 16 November 2026. Indonesian formats: `1.250`, `4,2%`, `Rp 4,2 M`, `Rp 850 jt`, `12 Nov 2026`, `Sen, 16 Nov`, `09.12`.
- The page header already carries the example note; do not repeat it per widget.
- Charts: pick units so plotted values are whole numbers below 1.000 (per-day counts, percentages, juta, miliar), so axis labels read the same in both number formats. Put the Indonesian headline figure in `figure` and `label` yourself. Set `data-locale="id-ID"` on `.evcal` and `.daterange`, Indonesian `data-noun` on `.dtable`, `data-more` and `data-less` on `[data-lds-more]`.
- `dashboard.js` turns the few strings `js/lds.js` writes in English (table info line, date range presets, calendar buttons) into Indonesian. Once the system localizes these itself, that block can go.
- `.map` shows real map tiles; markers and labels on top are the example's. Keep place names on markers fictional.

## 3. Which component for which widget

Every widget starts in `skills/lampung-design-system/references/components.md`. Read the component file before writing markup and copy its markup exactly. **The catalog is growing while these pages are built (more card and chart components are being added), so re-read `components.md` before each page instead of relying on memory or on this table.**

| Widget | Use | Notes |
|---|---|---|
| Page layout | `.dash-grid` + `.dash-span-N` (this folder's CSS), or `.dash-kpis`, `.auto-grid`, `.stack`, `.cluster`, `.split-2` | Twelve columns; spans collapse on their own (see `dashboard.css`). Gaps 16. Between page blocks the `main` gives 28. |
| KPI strip | `.dash-kpis` holding `article.kpi` cards ([kpi-card](../../skills/lampung-design-system/references/components/kpi-card.md)) with `.delta` ([trend-delta](../../skills/lampung-design-system/references/components/trend-delta.md)) and `.kpi__spark` or `.kpi__bars` | The delta's color is meaning (good or bad), its arrow is direction; say what it compares with in `.kpi__meta`. `data-lds-grow` on the strip for the entrance. For two to four plain figures without cards: `.stat-row` (`pengguna.html`). |
| Chart card | `section.chart-card` with `.chart-card__head` (question as title, sub line, a `.seg.chart-card__range` with `data-lds-chart-for`), `.chart-card__figure`, a `.chart[data-lds-chart]`, `.chart-card__foot` ([chart-card](../../skills/lampung-design-system/references/components/chart-card.md), [area-chart](../../skills/lampung-design-system/references/components/area-chart.md), [bar-chart](../../skills/lampung-design-system/references/components/bar-chart.md), [donut](../../skills/lampung-design-system/references/components/donut.md)) | Charts are drawn from JSON by `drawChart`; never hand-draw SVG for a data chart. Title is the question the chart answers. Series colors only from the chart tokens. Ranked lists: `.hbars` ([ranked-bars](../../skills/lampung-design-system/references/components/ranked-bars.md)). Also gauge, funnel, target bar: see the catalog. |
| Table card | A `section.stack` with a `.section__head` (`h2.section__title-sm` + `.section__sub`) and a link or button at the end, then `.dtable[data-lds-table]` ([data-table](../../skills/lampung-design-system/references/components/data-table.md)) | Never put a `.table-box` inside a `.card` (ring in a ring). | List card | `.list` (white, ring) or `.list--fill` of `.lrow`s ([list](../../skills/lampung-design-system/references/components/list.md)), under a `.section__head` | Avatars, `lrow__sub` meta, a badge or `lrow__value` at the end, `lrow__chev` for links. |

| Files | `.file-grid > .file-tile` ([file-tile](../../skills/lampung-design-system/references/components/file-tile.md)) | Folders first. |

## 4. Page CSS rules (`dashboard.css`)

- Placement only: `display`, `grid-*`, `gap`, `width`, `max-width`, `min-width`, `margin` and `padding` on the 4 px grid, `order`, `position: sticky` and `top`, `align-*` and `justify-*`, `overflow` for a scroll area.
- Never: color, background, border, box-shadow, border-radius, font, opacity, transform, transition or animation. Those come from the system class. If you want them, you want a system component.
- Put your rules in a section `/* ---------- <slug> ---------- */` at the end of the file, class names `dash-<slug>__<part>`. Do not change other pages' sections or the shared ones; if a shared rule is wrong, say so.
- Inline `style` is fine for one-off placement (`--gap`, `--min`, a width), as the system docs do; repeated placement belongs in the file.
- Use the shared pieces first: `.dash-grid`, `.dash-span-3|4|5|6|7|8|9|12`, `.dash-kpis`, `.dash-fill` (a card that fills its grid row).

## 5. Data states (required)

Every widget that shows data has loaded, loading, empty (when it can be empty) and error states, and the Pratinjau keadaan (preview state) menu in the header switches all of them at once. Mark a widget with `data-states` and put each state in a child with `data-state-view`:

```html
<section class="chart-card" aria-labelledby="x-q" data-states>
  <div class="chart-card__head">…</div>                       <!-- no data-state-view: always shown -->
  <div data-state-view="loaded">…the chart…</div>
  <div data-state-view="loading" role="status" aria-label="Memuat pendapatan" hidden>….skel shapes of the real layout…</div>
  <div class="empty" data-state-view="empty" hidden>…title, why, one action…</div>
  <div class="alert alert--danger" role="alert" data-state-view="error" hidden>…what failed, nothing lost, <button data-state-retry>Coba lagi</button></div>
</section>
```

- `data-state-retry` on a button shows loading for 0.9 s, then the loaded view.
- A missing view falls back to loaded (a KPI strip has no empty state).
- A data table shows its own states as rows: give the `.dtable` `data-states` and `tr.dtable__state[data-state="loading|empty|error"]` rows (`pengguna.html`), and forward the menu: `table.addEventListener('dash:state', (e) => tableState(table, e.detail.state === 'loaded' ? 'ready' : e.detail.state))`.
- Skeletons mirror the real layout (same row heights and widths). Empty states say why and offer the one action that fills them; empty because of a filter offers Clear filters.
- `showState('loading')` from `./dashboard.js` switches the whole page from code (for example after a period change; see `ringkasan.html`).

## 6. Interactions and motion

- Every control does something real: filters filter, sorting sorts, buttons give feedback (`setLoading` then `notify`, `morphText`, `shake` on refused input with the reason in words), deletes offer Urungkan.
- Use the system's motion only (`.stagger`, `.view-in`, rolling numbers with `.roll` + `setRoll`, `data-lds-grow` for charts). Do not write keyframes or transitions in page CSS.
- Forms: `.form`, `.form__row`, `.field`, `.control`; validate on submit, mark the control `is-invalid`, put the reason in `.field__help--error`, `shake()` it, focus it.
- Keep focus sensible: return it to the trigger when a layer closes (the system does it for its layers), give every icon-only button an `aria-label`, use real `button` and `a` elements.

## 7. Verify before you hand over

1. `npm run build:examples` must pass. It fails on unknown classes, unknown icons, links to missing files, duplicate ids, `data-lds-menu` / `aria-controls` / `aria-labelledby` pointing nowhere, em dashes and missing front matter. It also fails when a page does not show the example note exactly once. Warnings about links to pages without a source yet are fine. While several pages are in progress, `node scripts/build-examples.mjs --only slug1,slug2` builds and checks just those.
2. `node scripts/build-docs.mjs` still passes if you touched the system.
3. Open `http://localhost:5173/docs/examples/dashboard/<slug>.html` (`npm run serve`) at 360, 390, 768, 1024, 1366 and 1600 px in light and dark: no console errors, `document.documentElement.scrollWidth <= innerWidth` at every width (wide tables and plots scroll inside their own box), menus and popovers stay on screen, nothing cramped or floating.
4. Use every control on the page, by mouse and by keyboard, and switch Pratinjau keadaan through all four states.
5. Take screenshots at 390 and 1366 in both themes and look at them.
