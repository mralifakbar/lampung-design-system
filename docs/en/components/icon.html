Icon

Icons are text: <span class="ic" aria-hidden="true">search</span>, drawn by a ligature font from the Solar set. Only names in icons/icons.json exist; any other name renders nothing, silently.

descriptionView as Markdown

Usage

Use it when

  • A label gains speed from a glyph people already know: search, add, download, calendar, settings.
  • Inside components that expect one: a button before its label, an icon button, a list row, an alert, a badge, an empty state.
  • A selected or filled state needs the bold style (ic--fill): a pressed toggle, a liked heart, a current tab.

Use something else when

  • A clickable icon with no text: use Icon button. The bare .ic is decoration; the button gives it a 44 px target, a name and a tooltip.
  • A small colored square that sets a row apart in a settings list: use List. Use .lrow--icon with .lrow__icon.
  • A person or organization: use Avatar.
  • A dot that says online, offline or live: use Status dot.
  • An icon that changes meaning on press (copy to copied, play to pause): use Icon swap.

Where it goes. Before the text it explains, 6 to 10 px away (components set the gap). Icons follow currentColor, so they take the text color of their parent; muted icons use --text-subtle or --text-muted. On phones the same sizes hold; never scale icons down to fit.

Examples

Anatomy

PartWhat it is
.icRequired. A <span> whose text is the icon name. 20 px, line style, 1em square, never wraps.
.ic--fillThe bold (filled) style from the second font, for selected and filled states.
.ic--sm / .ic--lg16 px (dense rows, badges, small buttons) / 24 px (page headers, empty states).
aria-hidden="true"Required when there is visible text next to it, which is almost always.

Variants and sizes

Class or attributeWhen
ic--fillBold style for selected, pressed and filled states. Pressed toggles, alert icons, list icon chips and file tile thumbnails switch to it automatically.
ic--sm16 px.
ic--lg24 px.
style="color: …"Only with tokens (--text-subtle, --accent-text, --success-text); never a raw hex.

Motion and microinteractions

  • Icons do not animate on their own. When one changes meaning, use icon swap: the old glyph scales to 0.5 and blurs 4 px in --d-fast while the new one settles on --spring-snappy over --d-snappy.
  • Chevrons that open something rotate 180 degrees on --spring-smooth (split button, tool call, accordion); that rotation belongs to the component.
  • No spinning icons for loading: use the spinner.

Accessibility

  • Decorative (next to text): aria-hidden="true". This is the default; without it a screen reader reads the ligature name ("calendar_month").
  • Meaningful and alone: role="img" and an aria-label in plain words.
  • Icon-only controls are icon buttons with an aria-label; the label goes on the button, not the span.
  • Never rely on the icon color alone for status; pair it with words.

Do and don't

check_circleDo

  • Check the name against icons/icons.json before using it.
  • Pick icons for meaning; if none fits, use no icon.
  • Use the fill style for "on", the line style for "off".

cancelDon't

  • Use an <svg> or an emoji where a system icon exists, or mix in another icon set.
  • Invent names: arrow_right, trash and user render blank (the names are arrow_forward, delete, person).
  • Decorate headings or "AI" features with sparkles or similar glyphs.

Behavior and code

Plain HTML. None. To add an icon: add "my_name": "solar-base-name" to icons/icons.json and run npm run build:icons.
