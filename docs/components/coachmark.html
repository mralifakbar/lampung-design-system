Coachmark

An inverse card that points at one part of the interface with a short explanation, in a tour of at most three steps. Always skippable.

Usage

Use it when

  • A new feature lives somewhere the person would not look, and one sentence pointing at it saves a support question.
  • A short first-run tour (one to three steps) through a dense screen, such as the exam editor or a grade book.

Use something else when

  • A one-time tip that does not need to point at a control: use Hints.
  • Explaining a term or an icon on hover or focus: use Tooltip.
  • Rich, interactive content opened by a click: use Popover.
  • Announcing something about the whole app: use Banner.
  • The interface needs a tour of more than three steps: use Empty state. Usually the screen needs a better first-run state, not a longer tour.

Where it goes. Directly under the control it explains, with its arrow aimed at it (the arrow is on the top edge, placed with --arrow). The container must be positioned (position: relative). On phones keep it inside the screen width (280 px card) and below the target.

Examples

Anatomy

PartWhat it is
.coachRequired. A 280 px inverse card, absolutely positioned inside a relative container; set top/left (or transform) to place it.
.coach::beforeThe arrow on the top edge. Move it with --arrow (left offset, default 24 px); it glides when the value changes.
.coach__step"Step 1 of 3".
.coach__titleRequired. What this is, in a few words.
.coach__bodyOne sentence: why it helps.
.btn.btn--smSkip (inverse tint) and Next or Done (.btn--sm.is-primary, accent).
.is-litOn the target: a ring in the accent with a gap, so the person sees what is meant.

States

StateHow
openThe card is placed under the target and the target has .is-lit.
next stepMove the card (transform) and the arrow (--arrow); change the text; move .is-lit.
skipped or doneRemove the card and .is-lit, and remember it so the tour never shows again.

Motion and microinteractions

  • Between steps the card glides with transform on --spring-smooth (--d-smooth, 560 ms) and the arrow slides with left on the same spring, so the eye follows to the new target instead of losing it.
  • New step text may rise in with lds-rise over --d-standard (240 ms) on --ease-enter.
  • Opacity uses --d-standard on --ease-enter. Reduced motion: moves become 120 ms linear changes.

Accessibility

  • role="dialog" (non-modal) with aria-labelledby the title and aria-describedby the body. Move focus to the Next button when it opens, and back to the target when it closes.
  • Escape must skip the tour; wire it in the app (there is no built-in behavior).
  • The page stays usable behind it: no scrim, no focus trap.
  • The lit ring is not the only cue; the text names the control ("Filter by course").

Do and don't

check_circleDo

  • Point at one control per step, three steps at most.
  • Always offer Skip, and never show a finished tour again.
  • Start the tour only after the screen has loaded and the person is idle.

cancelDon't

  • Chain coachmarks across pages.
  • Explain what the label already says ("This is the search button").
  • Cover the control it points at.

Behavior and code

Plain HTML. No built-in behavior: placing the card, moving --arrow, toggling .is-lit, Escape and remembering completion are up to the app.
