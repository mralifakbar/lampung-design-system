Confirm in place

A destructive action that asks, works and reports inside one pill: rest, then "Delete 3 files?", then Deleting, then Deleted with Undo. The pill springs to fit each sentence, so nothing around it jumps and nobody has to deal with a dialog for a small, undoable action.

Usage

Use it when

  • Deleting, removing or leaving one thing, or a small selection, that can be undone: files, a member, a group, a saved search.
  • The action sits in a toolbar, a card header or a row, and a dialog would feel heavier than the action.

Use something else when

  • The action cannot be undone or affects many people (delete a course for every student): use Alert dialog.
  • A costly but not dangerous commit (submit an exam, pay): use Hold to confirm. Or slide to confirm on phones.
  • Removing a row by gesture: use Swipe actions.
  • The result happened somewhere else on the page: use Toast. Offer Undo there.

Where it goes. Where the action already lives: the end of a file toolbar, a card header, the trailing edge of a list row. Give it room to grow: it can be about twice its resting width while asking.

Examples

Anatomy

PartWhat it is
.confirmRequired. The pill, data-lds-confirm. Height 44, width follows the current face. data-face says which face shows.
.confirm__face--restRequired. Holds .confirm__arm (data-act="arm"): icon plus the action, in danger text.
.confirm__face--askRequired. .confirm__q (the question with the object), a plain Cancel (data-act="cancel") and a btn--danger (data-act="confirm").
.confirm__face--busyRequired. Spinner plus a shimmering verb ("Deleting"), role="status".
.confirm__face--doneRequired. Check plus the result sentence and .confirm__undo (data-act="undo"), role="status".

States

StateHow
restdata-face="rest": danger tint, the action with its icon.
askdata-face="ask": base surface with a ring; focus moves to Cancel. Escape or Cancel returns to rest.
busydata-face="busy": spinner and shimmer; shown at least 600 ms so it never flickers.
donedata-face="done": success tint, the result and Undo (focused). Returns to rest after data-reset ms (default 5000).
failedIf the promise rejects, it returns to rest and shakes; say why next to it.

Motion and microinteractions

  • Width: the pill measures the next face and transitions its width on --spring-snappy (--d-snappy, 360 ms); background color cross-fades over --d-standard.
  • Faces: the old face leaves in 120 ms on --ease-exit (fade, 2 px blur, scale 0.98), held centered so text never slides sideways; the new face enters in 200 ms on --ease-enter after 60 ms, or after 150 ms when the pill is growing so words are never cut off.
  • Done: the check pops on --spring-momentum (360 ms), a small earned bounce for a finished action.
  • Failure: shake() (360 ms, two oscillations) plus an error haptic.
  • Interruption: every step is a transition on the current width; arming and cancelling quickly reverses smoothly.
  • Reduced motion: width changes in 120 ms, faces swap at once, no pop and no shake.

Accessibility

  • Every face holds real buttons. Arming moves focus to Cancel (the safe choice); done moves focus to Undo; cancel and reset return it to the arm button.
  • The busy and done faces are role="status", so "Deleting" and "Deleted 3 files" are announced.
  • The question names the object ("Delete 3 files?"), so it makes sense out of context.

Do and don't

check_circleDo

  • Name the object in the arm label, the question and the result.
  • Call e.detail.wait(promise) so the busy face lasts as long as the real work.
  • Make Undo really restore, and listen for lds:undo.

cancelDon't

  • Use it for irreversible actions; use an alert dialog.
  • Put two confirms side by side in one row.
  • Show a toast as well; the pill already says it.

Behavior and code

Plain HTML. init() wires [data-lds-confirm]. On confirm it emits lds:confirm with { wait }; pass your promise to wait to hold the busy face (a rejection returns to rest with a shake). Without wait it settles after 700 ms. lds:undo fires on Undo. data-reset sets how long the done face stays (ms). Light haptic on arm, success haptic on done.
