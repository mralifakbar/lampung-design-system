Text field

A single line of free text with its label above and a helper line below. The helper turns into the error message, so the layout never jumps.

Usage

Use it when

  • People type a short free value: a name, an email, a student ID, a school name.
  • A form needs a field that validates (after the first blur, then live) and says what to fix in words.
  • A value needs a leading icon, a unit, or one trailing action such as clear (.control__btn).

Use something else when

  • More than one line of text (a note, a reason, a description): use Textarea.
  • Money or another number with a unit: use Amount field. Same .control, with the currency as a prefix and a numeric keyboard.
  • Finding things in a list or page: use Search field. Filled shape, no label, Cancel on phones.
  • A password or PIN: use Password field.
  • A one-time code from SMS or email: use One-time code.
  • The answer is one of a known list: use Select. Or a combobox when the list is long and people type to find.
  • A date: use Date field.
  • Several short values (topics, emails to invite): use Tag input.

Where it goes. Inside a form: fields stack 20 px apart in .form, short pairs (first and last name, city and postcode) share a .form__row, and the buttons end the form in .form__actions. Full width of its column on phones; on wide screens cap the form at about 560 px instead of stretching a field across the page.

Examples

Anatomy

PartWhat it is
.fieldRequired. Column wrapper, 8 px between label, control and helper.
.field__labelRequired. A <label for> above the control. A <span> inside it is the quiet right-hand note ("Optional", a counter).
.controlRequired. The 44 px box with the border, focus ring and states. Holds the <input>, which fills the rest of the row.
.control > .icOptional leading icon, 19 px, muted; turns accent while the field has focus.
.control__suffixOptional unit or prefix text (Rp, kg, %, @campus.ac.id).
.control__btnOptional trailing 30 px icon button (clear, reveal, open calendar). Needs an aria-label.
.field__helpHelper text under the control. Add --error (with an error icon) or --ok (with check_circle) to turn it into feedback in the same place.

Variants and sizes

Class or attributeWhen
.control > .icLeading icon for a field whose kind is not obvious from the label (mail, phone, school).
.control__suffixUnit or prefix text; see amount field.
.control__btnOne trailing action: clear, reveal (password field), open a calendar (date field).
.field__help--error / --okThe helper line as feedback, with an error or check_circle icon.

States

StateHow
hoverThe border darkens to --text-subtle (devices with hover).
focusAutomatic via :focus-within: 1.5 px accent edge plus a 4 px --accent-ring halo; the leading icon turns accent.
.is-invalid + aria-invalid="true"Danger edge and halo. Pair with .field__help--error and keep aria-describedby pointing at it.
.is-disabled + disabledFill background, quiet border, muted text. Put disabled on the input and the class on .control.
autofillHandled by the system: the browser paint is clipped to the text and the field keeps its own background. On a field placed on another color set --autofill-bg on it.
on a filled surfaceInside .card--fill, .list--fill, .kv-list or .spotlight the control switches to the base color by itself (never fill on fill).

Motion and microinteractions

  • Focus ring and border: box-shadow and background-color transition in --d-fast (160 ms) on --ease-standard; the leading icon color follows in the same time. Leaving focus reverses the same transition, so tabbing fast through a form never flickers.
  • Errors appear in place: swap the helper text, do not slide a new line in. If a submit is refused, shake the field once (two short oscillations, 360 ms) instead of animating the message.
  • Validate after the first blur, then live on each input: the message changes as soon as the value is fixed, so the person sees the green state while still typing.
  • Reduced motion: every transition becomes 120 ms linear; nothing in a field travels, so behavior is otherwise the same.

Accessibility

  • Every input has a <label for>. Never rely on the placeholder; it disappears on typing and is low contrast by design.
  • Point aria-describedby at the helper so the format hint and later the error are read with the field. Set aria-invalid="true" together with .is-invalid.
  • Use the right type, inputmode and autocomplete (email, tel, name, given-name, organization) so phones show the right keyboard and browsers can fill it.
  • On touch screens the input renders at 16 px or larger (the system does this under pointer: coarse), so iOS never zooms the page on focus. Do not set a smaller font on .control input.
  • A .control__btn is a real <button type="button"> with an aria-label naming its effect ("Clear course name").

Do and don't

check_circleDo

  • Write the label as a noun ("Email"), the helper as the format or why you ask ("We send receipts here").
  • Mark the rare optional field with "Optional" in the label span instead of starring every required one.
  • Keep one column on phones; pair only short related fields with .form__row.

cancelDon't

  • Put the label inside the field as a placeholder, or float it.
  • Show an error while someone is still typing their first attempt.
  • Write a new box style for a field (rounded pill, underline only, shadow). Use .control.
  • Disable a field without saying why in the helper.
