Search field

The filled, label-less field for finding things: courses, students, questions. On phones, focusing it slides in a Cancel button that clears and leaves search.

Usage

Use it when

  • People narrow a list or page by typing: search courses, filter a student table, find a question in a bank.
  • A phone screen has a search bar under the large title (with Cancel, data-lds-search).
  • A toolbar above a table or grid needs a compact search box.

Use something else when

  • Searching commands and pages across the whole app from anywhere (Ctrl K): use Command palette.
  • Picking one value from a long list for a form field: use Combobox. A combobox stores the choice; a search field only filters what is shown.
  • A labelled form value (a name, an email): use Text field.
  • Narrowing by a few fixed categories: use Chips. Filter chips next to the search field are fine.

Where it goes. At the top of what it filters: under the large title on a phone screen, in the toolbar above a table or list on wide screens, at the top of a sidebar for long navigation. Give it the width of the content it filters, about 520 px at most on wide screens.

Class or attributeWhen

States

StateHow
restRecessed fill, no border, no hover border.

Motion and microinteractions

  • Cancel enters by max-width 0 to 80 px and margin-left 0 to 12 px on --spring-smooth (560 ms), with opacity in --d-fast. The field shrinks along with it, so nothing jumps. Leaving reverses the same transitions.
  • Focus ring: --d-fast (160 ms) on --ease-standard.
  • Results that change while typing should not stagger in on every key; swap them at once, or use a short list stagger only for the first load.
  • Reduced motion: transitions become 120 ms linear; Cancel still appears.

Accessibility

  • No visible label, so the input needs aria-label ("Search courses"). Wrap a page-level search in <form role="search"> when Enter submits.
  • Use enterkeyhint="search" so the phone keyboard shows a Search key. Prefer type="text": type="search" adds a second native clear button that the system does not hide.
  • Announce the result count or the no-results message in a role="status" region so screen reader users know the list changed.
  • Cancel and clear are real buttons (type="button"); clear has an aria-label.

Do and don't

check_circleDo

  • Name what is searched in the placeholder ("Search courses").
  • Filter as people type for local lists; debounce about 180 ms for server searches.
  • Keep the query when people come back to the list.

cancelDon't

  • Give the search field a border and label like a form field.
  • Use it to choose a form value; that is a combobox.
  • Show "No results" without saying what to try.

Behavior and code

Plain HTML. data-lds-search on .search-wrap: focus adds .is-active; Cancel clears the input, dispatches input, removes .is-active and blurs. Filtering and the clear button are yours.
