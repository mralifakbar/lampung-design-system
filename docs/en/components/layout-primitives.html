Layout primitives

Seven small classes that lay out everything between components: stack, cluster, auto-grid, split-2, center, measure and sr-only. Reach for them before writing display: flex or grid by hand.

Usage

Use it when

  • You need to place components next to or under each other: a column of cards (stack), a row of buttons or badges that may wrap (cluster), a grid of tiles that reflows by width (auto-grid).
  • A page has a narrow side column and a main column that should collapse to one column on tablets and phones (split-2).
  • Text or a single block must sit in the middle of its area (center) or long text must keep a readable line length (measure).
  • Something must be read by screen readers but not shown (sr-only): a table behind a chart, "opens in a new tab" after an external link.

Use something else when

  • Fields, field pairs and the buttons that end a form: use Form layout. form, form__row and form__actions already carry the right spacing and the phone behavior.
  • A page made of titled sections with dividers between them: use Sections.
  • The app frame: sidebar, top bar, scrolling main area: use App shell.
  • A row of attached buttons acting on one object: use Button group. cluster only spaces things; it does not join them.
  • A horizontally scrolling row of cards: use Carousel.
  • Two panes the reader resizes by dragging: use Resizable split.

Where it goes. Anywhere inside a page, nested as deep as needed: a stack of sections, each holding a cluster of actions and an auto-grid of cards. They carry no color, padding or radius, so they never compete with the components inside them. split-2 collapses to one column below 860 px; auto-grid drops columns on its own as the width shrinks.

Examples

Anatomy

PartWhat it is
.stackVertical flow. gap defaults to 12 px; set --gap inline (style="--gap: 20px") for groups (20 to 28) or sections (48).
.clusterHorizontal row that wraps, items centered on the cross axis. --gap defaults to 8 px.
.auto-gridAs many equal columns as fit, each at least --min wide (default 240 px), never wider than the container. --gap defaults to 12 px.
.split-2Two columns: a side column --side wide (default 320 px) and a main column that takes the rest. --gap defaults to 28 px. One column below 860 px.
.centerGrid that centers its child on both axes and centers text.
.measureCaps width at --size-measure (680 px), about 70 characters of body text.
.sr-onlyVisually hidden, still in the accessibility tree.

Variants and sizes

Class or attributeWhen
--gapSpacing on stack, cluster, auto-grid, split-2. Stay on the 4 px grid: 8 to 12 for related items, 20 to 28 for groups, 48 for sections.
--minauto-grid only: the narrowest a column may get before the grid drops a column. 160 for small tiles, 240 for cards, 320 for wide cards.
--sidesplit-2 only: the side column width.

Motion and microinteractions

  • None. Layout primitives never animate. When the children change, use list stagger for arrivals or height expand for growth inside them.
  • Reflow on resize is instant by design; do not add transition on grid-template-columns.

Accessibility

  • They change only visual placement. Keep the DOM order the reading order: split-2 puts the side column first in the source, so put the content that should be read first there, or swap the columns.
  • Never use order or flex-direction: row-reverse to rearrange content inside them; keyboard focus follows the source, not the screen.
  • sr-only content is announced and is part of the accessible name of its parent link or button. Do not put focusable elements inside it.
  • Use headings and landmarks (<main>, <nav>, <section aria-labelledby>) for structure; a stack is just a <div>.

Do and don't

check_circleDo

  • Set spacing with --gap on the parent instead of margins on the children.
  • Nest primitives: a stack of clusters, an auto-grid inside a split-2 main column.
  • Put min-width: 0 on custom children of your own grids; the primitives already do it for theirs.

cancelDon't

  • Write a new .my-row { display: flex; gap: 12px } class when cluster does the job.
  • Use auto-grid for a form; fields need form layout so labels and errors line up.
  • Add backgrounds, padding or radius to a primitive. Wrap the content in a card instead.
