Checkbox

A native checkbox with a drawn tick, for independent yes or no choices that are saved with a form. Several can be on at once; each label says what turning it on means.

Usage

Use it when

  • Several independent options in a form, any number of which can be on: which notifications to receive, which subjects to include.
  • One agreement before submitting: "I have read the exam rules".
  • Selecting rows in a list or table to act on them together (with a "select all" that can be mixed).

Use something else when

  • A setting that takes effect immediately, with no Save button: use Switch.
  • Exactly one of a few options: use Radio.
  • Filters that apply as they are tapped, shown as a row: use Chips.
  • Options that need a description, a price or an icon each: use Radio card. For one choice; for several, checkboxes with a small second line.
  • Marking a task done in a checklist that is not a form: use List. Checked rows (.lrow--check) show what is done.

Where it goes. In a form, stacked in a column 12 px apart, inside a <fieldset> with a <legend> when they belong to one question. In list and table rows, at the start of the row. Never in a horizontal row of more than two on phones.

Examples

Anatomy

PartWhat it is
label.checkRequired. The whole row is the hit area; text wraps beside the box.
input[type=checkbox]Required. The native input, invisible over the box, so keyboard, forms and screen readers work as usual.
.check__boxRequired. The 22 px box with an SVG: path.tick for checked, path.dash for mixed. aria-hidden.
.check__textRequired. The label text; a small inside adds a quiet second line.
fieldset + legendGroups related checkboxes under one question.

States

StateHow
checkedAccent fill with the primary finish; the tick draws in.
.is-mixed (on .check) + input.indeterminateAccent fill with a dash. Set indeterminate = true on the input in JS so it is announced as mixed.
hoverThe box edge darkens to --text-subtle.
:activeThe box sinks to 0.88 in 90 ms.
focus-visibleFocus ring on the box, from the input.
disabledThe box at 40 % opacity; say why in the small line.

Motion and microinteractions

  • Tick: stroke-dashoffset 20 to 0 in 260 ms on --ease-enter, after a 40 ms delay so the fill lands first. Unticking erases it in 160 ms on --ease-exit; leaving is faster than arriving.
  • Fill and edge: background-color and box-shadow in --d-fast (160 ms) on --ease-standard.
  • Press: scale(0.88) in 90 ms, back on --spring-snappy (360 ms). Feedback starts on pointer down.
  • Mixed: the dash draws in 200 ms on --ease-enter.
  • Reduced motion: transitions become 120 ms linear; the tick still appears.

Accessibility

  • A real <input type="checkbox"> inside the <label>: Space toggles, the label is the name, forms submit it.
  • Group with <fieldset> and <legend> so the question is read with each option.
  • Mixed state: set input.indeterminate = true (there is no HTML attribute); .is-mixed alone is only visual.
  • Keep the label text on the label; the second line in small is read as part of it.

Do and don't

check_circleDo

  • Phrase each label as the thing that will be true when it is on.
  • Start unchecked unless the person chose before; never pre-tick consent.

cancelDon't

  • Use a checkbox for an instant setting; use a switch.
  • Use a single checkbox as an on and off toggle between two named states ("Light or dark"); use a segmented control.
  • Draw a custom box or icon tick; use .check__box with its SVG.
